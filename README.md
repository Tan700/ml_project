# Amazon ML Challenge 2026: Business Entity Resolution Baseline

An end-to-end Machine Learning solution for resolving noisy, unstructured business entity records across multiple independent data sources.

---

## 1. Problem Overview
In large-scale commercial platforms, business identity data originates from multiple independent data providers. Each provider contributes noisy, partial records lacking shared unique identifiers. Source 1 serves as the canonical deduplicated reference source. The objective is to identify all corresponding records from Source 2 and Source 3 for each Source 1 entity. 

A Source 1 entity can match:
- Zero records (Singletons)
- Exactly one record
- Multiple records across Source 2 and Source 3

Evaluation uses **macro-averaged F_0.5** across all Source 1 entities (including singletons), emphasizing precision over recall:
$$\text{F}_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$

---

## 2. Dataset Description
The dataset contains tab-separated files (`.tsv`) partitioned into `train/` and `test/` splits:
- **`*_source1.tsv`**: Canonical reference records (`S1-` IDs).
- **`*_source2.tsv`**: Secondary noisy provider (`S2-` IDs).
- **`*_source3.tsv`**: Tertiary noisy provider (`S3-` IDs, contains missing addresses and website domains).
- **`train_ground_truth.tsv`**: Mapping of `source1_entity_id` to comma-separated `matched_entity_ids` (or empty for singletons).

**Key Dataset Statistics:**
- **Training records:** 2,206,821 Source 1 entities; 5,034,616 Source 2 records; 5,285,603 Source 3 records; 7,638,365 ground truth links.
- **Test records:** 1,732,544 Source 1 entities; 4,887,273 Source 2 records; 5,082,316 Source 3 records.
- **Country distributions:**
  - Training: US (60%), India (40%).
  - Test: India (47.3%), US (38.3%), France (14.4%).
  - Country is an open-set string. Matches strictly preserve country boundaries (0 cross-country matches).

---

## 3. Normalization Pipeline (`src/normalization.py`)
Both original and normalized values are retained:
- **Business Names:**
  - NFKD Unicode normalization to standardize accents and non-ASCII characters.
  - Case folding to lowercase.
  - Standardizing `&` to `and`.
  - Legal suffix standardization (e.g. `incorporated` $\to$ `inc`, `private limited` $\to$ `pvt ltd`, `s.a.r.l.` $\to$ `sarl`).
  - Whitespace and punctuation normalization while retaining alphanumeric tokens.
- **Addresses:**
  - Street abbreviation canonicalization (`street` $\to$ `st`, `road` $\to$ `rd`, `avenue` $\to$ `ave`, `boulevard` $\to$ `blvd`, `suite` $\to$ `ste`, `apartment` $\to$ `apt`, `floor` $\to$ `fl`, `p.o. box` $\to$ `pobox`).
  - Removal of non-essential delimiters while preserving building numbers, street names, and postal codes.

---

## 4. Multi-Strategy Blocking Engine (`src/blocking.py`)
To avoid an impossible $1.7\text{M} \times 10\text{M}$ Cartesian product, an inverted index is constructed within each country partition using the union of several complementary strategies:
1. **Exact Normalized Name**: Maps exact normalized names to entity IDs.
2. **Name Prefix**: 6-character normalized name prefixes to handle slight suffix or ending spelling variations.
3. **Significant Name Tokens**: Tokens of length $\ge 4$, excluding common legal stop-words (`inc`, `corp`, `pvt`, `ltd`, `services`, `solutions`).
4. **Address Tokens & Postal Codes**: 5- and 6-digit postal codes and distinct street address tokens.
5. **Character Trigrams**: Fast n-gram signatures for fuzzy name lookup.

High-frequency blocks exceeding maximum capacity are pruned, and candidates per Source 1 entity are strictly bounded.

---

## 5. Feature Engineering (`src/features.py`)
For each candidate pair `(Source 1, Target)`, an 18-dimensional feature vector is computed:
- **Name Features:**
  - Exact match and normalized exact match indicators.
  - RapidFuzz Levenshtein ratio, WRatio, and token-set ratio.
  - Jaccard token overlap.
  - Absolute length difference and length ratio.
- **Address Features:**
  - Exact match and normalized exact match indicators.
  - RapidFuzz ratio and token-set ratio.
  - Jaccard address token overlap.
  - Address length difference.
- **Contextual & Structural Features:**
  - Country equality flag.
  - Digit / numeric token Jaccard overlap.
  - Postal code exact overlap.
  - Target source indicator (`S2` vs `S3`).

---

## 6. Machine Learning Model (`src/model.py`)
- **Baseline:** L2-regularized Logistic Regression.
- **Primary Model:** LightGBM (Gradient Boosted Decision Trees).
- **Training Strategy:**
  - Entity-level split: 80% train / 20% validation.
  - Positive pairs: candidate pairs present in ground truth.
  - Negative pairs: candidate pairs generated by blocking but absent from ground truth.
  - Balanced negative subsampling (5 negatives per positive) to avoid skew while teaching the tree hard boundary distinctions.

---

## 7. Validation & Threshold Selection (`src/evaluate.py`)
The official metric is macro-averaged F_0.5 per Source 1 entity. Because F_0.5 heavily penalizes false merges (2x weight on precision), candidate pairs are evaluated across thresholds `[0.50, 0.60, 0.70, 0.75, 0.80, 0.85, 0.90, 0.95]`. The optimal threshold maximizing validation F_0.5 is selected and applied to test inference.

---

## 8. Final Test Inference & Output Generation (`src/predict.py`, `src/submission.py`)
- Inference runs in country-partitioned streaming batches (France, US, India) to maintain low memory usage (< 800 MB RAM).
- Outputs generated:
  - **`output/candidate_pairs.tsv`**: Final candidate set considered before thresholding.
  - **`output/matching_results.tsv`**: Final matched entity IDs (strictly a subset of candidates).
- Compliance with formatting rules:
  - Every test Source 1 entity has exactly one row.
  - Empty string for singletons.
  - No duplicate entity IDs.
  - Only valid test `S2-` and `S3-` IDs.

---

## 9. Reproducibility & Running the Pipeline
Install requirements:
```bash
pip install -r requirements.txt
```

Run the complete pipeline end-to-end:
```bash
python src/main.py
```

Run the official submission validator:
```bash
python utils/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir dataset/test
```
